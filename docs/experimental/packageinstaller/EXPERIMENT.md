# 应用包管理组件净化（实验性）

入口：**功能 → 实验性功能 → 应用包管理组件净化**。目标为 `com.miui.packageinstaller`，六个开关独立配置、默认关闭，沿用模块既有的偏好同步、作用域申请和 Hook 状态机制。

## 使用与范围

将应用包管理组件加入模块作用域，启用所需选项后重启该组件进程；更改在下次调用组件时生效。状态回报可能延迟，调用安装器后可返回本页查看。启用功能可能增加安装器启动耗时，当前没有量化耗时数据。

| 选项 | 行为 |
| --- | --- |
| 禁用推广 | 控制应用安装器的广告推广。 |
| 禁用风险检测 | 阻断安装器本地和云端的风险检测，保留 Android 签名及安装授权校验。 |
| 阻断云端配置下发 | 拦截安装器从云端获取配置，不清除已有缓存。 |
| 禁用安全守护提示 | 控制安装器安全守护提示，部分场景可能不生效。 |
| 禁用频繁安装应用信息检查 | 阻止安装器检查频繁安装的应用信息。 |
| 禁止安装时上传应用信息 | 阻止已识别通道自动上传安装应用的信息，同时影响相应的云风险判定结果、附加验证和推广。 |

当前环境检查限定 Android 17 / SDK 37、安装器主进程和无 split APK 的安装器。通过业务特征识别 Hook 入口，不将安装器版本号或 DEX 摘要作为兼容白名单。特征不明确时保留原行为并记录原因；这不保证所有设备、安装器构建或后续更新均兼容。

功能快照已由用户在 HyperOS 4 / Android 17、安装器 `5.4.5.1.2-20260618P (54512)` 的环境确认实机测试通过。该反馈覆盖当前测试环境，未进行所有网络路径的抓包验证，也不代表所有组合和场景均已覆盖。

## 状态与诊断

开关下的“已生效”表示对应功能的必需 Hook 组完整注册，不等同于所有业务路径均已触发或所有请求均被阻断。可选的推广展示入口不计入六项完整挂载状态。

页面保留刷新、复制、清除诊断。诊断区分业务识别、挂载、部分挂载、回调命中、实际替换、保留原行为及异步完成；计数为最后快照，零次不能证明原方法从未执行。诊断从本功能 Load 进入后开始，缺少回报不能单独证明模块未注入。

接收端校验发送 UID、模块版本、构建标识、开机号、目标进程及时间；记录最多 64 行、每行 384 字符。刷新只进行组件和固定 Intent 查询，不启动安装器、不读取待安装文件。清除只删除本模块诊断记录，不清除安装器数据或云配置缓存。

## 集成与撤回

Hook 实现在 `hook/.../packageinstaller/`，页面、诊断接收与诊断记录存储在 `app/.../experimental/packageinstaller/`，中英文资源分别位于 `values/installer_experiment.xml` 和 `values-en/installer_experiment.xml`。规则与诊断测试位于对应测试包。

app 侧通过 `InstallerExperiment` 接入配置注册、实验页入口及多级搜索；Hook 侧通过既有 `BaseLoad`、`BaseHook`、`HookEntryRegistry` 接入，只为安装器增加默认作用域。没有修改公共 Hook、偏好或状态接口，没有调用其他业务 Hook，没有新增运行依赖、权限、原生库或 Gradle 模块。

关闭某项开关后，需要重启目标进程使更改生效。开发侧撤回时，应撤回整个功能提交，包括注册表、作用域、Manifest、页面接线、文档及致谢；只删除业务目录会遗留编译引用。宿主文件已有后续修改时，应逐段审查 `git revert` 的冲突，避免覆盖其他功能。撤回不需要重构宿主接口，也不通过全局解除 Hook 或清除目标数据实现。
